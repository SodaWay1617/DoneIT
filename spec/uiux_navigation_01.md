# DoneIt — UI/UX Specification 01: Навигация

**Статус:** первая итерация редизайна  
**Область:** Desktop Sidebar, Mobile Navigation, Application Shell  
**Цель:** заменить существующую навигацию на единую адаптивную систему, не меняя функциональность страниц.

## 1. Общие требования

Переработать навигацию приложения DoneIt на основе предоставленного визуального референса.

Сохранить текущую цветовую гамму: светлый бежевый фон, кремовые поверхности, приглушённые бирюзовые акценты.

Интерфейс должен быть современным, компактным и удобным для ежедневного использования. Приоритет — функциональность, а не декоративные элементы.

**Ограничения:**

- Сохранить Spring Boot + Thymeleaf и текущий способ навигации.
- Не внедрять React, Vue или другие frontend-фреймворки.
- Не менять бизнес-логику, API, модель данных, авторизацию и права доступа.
- Не удалять существующие страницы или действия.
- Использовать общие Thymeleaf fragments и переиспользуемые CSS-компоненты.
- Не переписывать содержимое существующих страниц в рамках этой задачи.
- Поддерживать русский и английский языки через существующий механизм локализации. Все новые элементы навигации должны учитывать выбранный пользователем язык, без захардкоженных подписей.

## 2. Desktop Sidebar

### 2.1. Расположение

Для экранов шириной от 1024 px использовать постоянную левую боковую панель.

Ориентировочная ширина: 240 px.

Sidebar должен быть общим для всех основных страниц приложения.

Основная область контента занимает оставшуюся ширину экрана.

На широких экранах контент может иметь собственную максимальную ширину. При этом Sidebar остаётся у левого края.

### 2.2. Структура

Верхняя часть:

**DoneIt** — логотип или текстовое название, нажатие открывает экран «Сегодня».

Основная навигация:

1. Сегодня
2. Входящие
3. Бэклог
4. Календарь
5. Расписание
6. Аналитика

Отдельный раздел:

**Проекты**

- Все проекты
- MAIN
- Пользовательские проекты, доступные текущему пользователю

Нижняя часть Sidebar:

- Настройки

Профиль, запомненные устройства, выход, выбор языка и обучение находятся внутри настроек и не дублируются в навигации.

### 2.3. Проекты

Список проектов загружать из существующей системы.

Показывать только проекты, доступные текущему пользователю, включая общие.

Название проекта отображать в пользовательском виде, без технических суффиксов.

Заголовок «Проекты» кликабелен и открывает страницу управления проектами.

Рядом с заголовком предусмотреть кнопку `+` для создания проекта.

Список проектов должен быть раскрываемым.

При выборе проекта:

- открывается существующий список задач с фильтром выбранного проекта;
- выбранный проект визуально выделяется;
- фильтр не должен изменять задачи других проектов;
- должен оставаться вариант «Все проекты».

Обычный набор проектов должен помещаться без прокрутки. При большом количестве проектов или малой высоте окна допускается одна общая прокрутка основной части Sidebar. Отдельную вложенную прокрутку списка проектов не использовать; настройки остаются закреплены внизу.

### 2.4. Активное состояние

Текущий раздел визуально выделяется мягкой бирюзовой подложкой.

Для активного пункта использовать также более выразительный текст и/или иконку.

Выделение должно определяться текущим маршрутом и параметрами фильтрации, а не только локальным состоянием JavaScript.

Если пользователь открыл задачи конкретного проекта, выбранный проект должен быть очевиден.

### 2.5. Счётчики

При наличии данных показывать небольшие счётчики рядом с:

- Входящие;
- Бэклог.

Счётчики должны отражать реальные данные, полученные из backend.

Не создавать отдельные запросы к БД для каждого пункта меню, если данные можно получить агрегированно.

Не отображать нулевые счётчики.

## 3. Mobile Navigation

### 3.1. Общий принцип

Для экранов шириной менее 768 px использовать нижнюю навигационную панель.

Панель фиксируется внизу viewport и остаётся доступной при вертикальной прокрутке страницы.

Использовать пять пунктов:

| Пункт | Назначение |
|---|---|
| Сегодня | Основной список задач |
| Входящие | Новые задачи |
| Календарь | Календарное представление |
| Проекты | Управление проектами |
| Ещё | Остальные разделы и настройки |

Каждый пункт содержит иконку и короткую подпись на выбранном языке интерфейса.

Активный пункт выделяется бирюзовым цветом.

Для текущего раздела, доступного только через «Ещё», активным считается пункт «Ещё».

### 3.2. Меню «Ещё»

Нажатие открывает мобильную панель меню.

Предпочтительный вариант — выдвижная панель снизу (bottom sheet).

Содержимое:

**Разделы**

- Бэклог
- Расписание
- Аналитика
- Выполненные и закрытые

**Представления**

- Канбан

**Дополнительно**

- Настройки

Профиль, устройства, выход, язык и обучение доступны через настройки.

В меню должен быть доступ к каждому разделу приложения, не представленному в нижней панели.

Открытие и закрытие меню не должно приводить к полной перезагрузке страницы.

Меню закрывается при выборе пункта, нажатии на затемнённую область и кнопке закрытия.

Предусмотреть корректную работу клавиши Escape и управление фокусом.

### 3.3. Мобильные проекты

При открытии «Проекты» показывается существующая страница проектов.

Из неё пользователь может:

- открыть проект;
- создать проект;
- перейти к задачам проекта;
- управлять доступом в рамках существующих разрешений.

Выбор проекта должен использовать существующий механизм фильтрации.

Не создавать отдельную мобильную бизнес-логику проектов.

### 3.4. Создание задач

В рамках данного этапа сохранить существующую кнопку создания задачи.

Не добавлять одновременно несколько плавающих кнопок создания.

Единый механизм быстрого создания задач будет проработан на следующем этапе редизайна главной страницы.

## 4. Tablet

Для ширины от 768 до 1023 px использовать компактный вариант навигации.

Предпочтительное решение — сворачиваемый Sidebar, который открывается по кнопке меню.

Не пытаться одновременно разместить полноценный Sidebar и узкую рабочую область.

Поведение должно учитывать реальную доступную ширину, а не тип устройства.

## 5. Responsive и PWA

### 5.1. iPhone

Обеспечить корректную работу в Safari и установленном PWA.

Нижняя панель должна учитывать:

`env(safe-area-inset-bottom)`

Основной контент должен иметь нижний отступ, чтобы последние элементы страниц не перекрывались навигацией.

При открытии экранной клавиатуры навигация не должна перекрывать активное поле ввода.

Не допускать горизонтальной прокрутки всей страницы из-за навигационных элементов.

### 5.2. Touch

На сенсорных экранах минимальная удобная область нажатия для основных элементов — 44×44 CSS px. На desktop с точным указателем использовать компактные строки: 32 px для разделов, 30 px для проектов и значки 18 / 16 px соответственно.

В режиме запуска с главного экрана нижняя панель компактнее браузерной: основная высота 56 вместо 64 px, нижний отступ — половина `safe-area-inset-bottom`. Отступ контента после панели — 12 вместо 24 px. Браузерный режим не меняется. Режим определяется через `display-mode: standalone` и `navigator.standalone` для iOS; верхняя safe area и отступы меню «Ещё» сохраняются.

Не использовать hover как единственный способ доступа к функциям.

Пункты меню должны иметь достаточное расстояние друг от друга.

### 5.3. Breakpoints

Проверить следующие ширины:

- 320 px;
- 375 px;
- 390 px;
- 430 px;
- 768 px;
- 1024 px;
- 1440 px;
- 1920 px.

## 6. Компонентная структура

Предусмотреть переиспользуемые компоненты:

- `app-shell`
- `desktop-sidebar`
- `sidebar-navigation-item`
- `sidebar-project-list`
- `mobile-bottom-navigation`
- `mobile-more-menu`
- `navigation-badge`

Имена компонентов условные и могут быть адаптированы к существующей структуре проекта.

Использовать Thymeleaf fragments для общей разметки.

Визуальные параметры вынести в CSS custom properties:

- ширина Sidebar;
- высота мобильной панели;
- основные цвета;
- фон активного элемента;
- отступы;
- радиусы;
- размеры текста.

Не копировать одну и ту же навигационную разметку между страницами.

### 6.1. Локализация

- Использовать существующую систему переводов DoneIt для русского и английского языков.
- Не создавать отдельный механизм переключения языка.
- Добавить ключи локализации для новых элементов навигации, если их ещё нет.
- Использовать уже существующие ключи там, где это возможно.
- Переводить подписи разделов, меню, кнопок, подсказок и текстов доступности.
- Пользовательские названия проектов не переводить.
- При переключении языка сохранять текущий раздел и выбранные фильтры.
- Проверить отображение длинных английских и русских подписей.

## 7. Интеграция

Перед изменениями изучить существующие:

- маршруты контроллеров;
- Thymeleaf templates;
- CSS и JavaScript;
- логику фильтрации проектов;
- текущую навигацию;
- авторизацию;
- механизм локализации и выбора языка;
- настройки PWA.

Использовать существующие URL и обработчики.

Если маршруты имеют разные имена или структуру, адаптировать компоненты к текущей реализации.

Не создавать новые контроллеры без необходимости.

Убедиться, что активный пункт корректно определяется после полной загрузки страницы и при прямом открытии URL.

## 9. Вне рамок задачи

На данном этапе **не выполнять**:

- редизайн карточек задач;
- редизайн форм создания и редактирования;
- переработку Kanban;
- изменение календаря и расписания;
- изменение аналитики;
- изменение бизнес-логики проектов;
- изменение модели данных;
- внедрение SPA;
- переработку системы уведомлений.

## 10. Результат

После реализации DoneIt должен получить единый адаптивный навигационный каркас.

Все существующие страницы продолжают работать, но пользователь перемещается между ними через новую согласованную систему.

Следующие этапы редизайна должны использовать этот каркас без необходимости снова перерабатывать навигацию.

## 11. Результат реализации, 18 октября 2026

Навигационный каркас реализован на существующих Spring Boot / Thymeleaf. Рабочие URL, обработчики действий и правила доступа сохранены; новых контроллеров и миграций БД нет. Общие fragments находятся в `templates/app-shell.html`, стили и поведение — в `static/app-shell.css` и `static/app-shell.js`. Модель меню формируется `AppNavigationService` и подключается только к рабочим HTML-представлениям, не к login, API или ресурсам.

Все рабочие разделы доступны, включая канбан, выполненные и закрытые задачи, Plan / Fact, аналитику нагрузки, отчёты, запомненные устройства и обучение. Переход «Все проекты» действительно сбрасывает фильтр; выбор другого проекта не перезаписывается старым скриптом сохранения фильтров. Кнопка создания проекта ведёт к существующей форме `/projects#new-project`.

Проверено: 264 теста без ошибок. Chromium: 16 экранов на двух языках и всех восьми заданных ширинах. WebKit: основные экраны и сценарии на 390 / 768 / 1024 CSS px; финальная проверка списка и фокуса — на всех восьми ширинах в обоих движках. Проверены меню, Escape, закрытие по фону и кнопке, Tab / Shift+Tab, возврат фокуса, проекты, фильтры, язык, прокрутка длинных списков и имитация клавиатуры.

Пункты про реальный iPhone / Safari / установленное приложение оставлены открытыми намеренно: safe area и экранную клавиатуру необходимо проверить на устройстве после выкладки. WebKit под Windows не является реальным Safari или iPhone PWA.

Визуальный референс: [Интерфейс планировщика задач DoneIt](<Интерфейс планировщика задач DoneIt.png>).

## 12. Уплотнение Sidebar, 18 октября 2026

По результатам использования нижний блок сокращён до единственного пункта «Настройки». Профиль пользователя, запомненные устройства, выход, язык и обучение собраны на странице настроек. Имя пользователя также убрано из мобильного заголовка. Обучение подсвечивает раздел настроек.

В desktop-меню уменьшены строки, значки и отступы. У списка проектов больше нет отдельного ограничения высоты и внутреннего scrollbar: при необходимости прокручивается только основная часть Sidebar. Дублирующие подпункты аналитики убраны из Sidebar; они остаются в переключателе страниц аналитики и мобильном меню.

Проверено: 265 тестов без ошибок. В Chromium и WebKit восемь проектов и все основные разделы помещаются без прокрутки на экранах 1280×720, 1440×768 и 1920×900 CSS px. Для окна высотой 500 px и длинного списка работает одна общая прокрутка. Проверены настройки, профиль, язык, устройства, обучение, выход и меню на ширинах 320 / 390 / 768 px. На сенсорных экранах сохранены области нажатия 44 px.

## 13. Нижняя панель PWA

По результатам проверки на iPhone уменьшено свободное место под пунктами нижней панели только для standalone-режима. При safe area 34 px общая высота панели сокращается с 98 до 73 px, а нижний отступ контента — со 122 до 85 px. В браузере с адресной панелью размеры остаются прежними.

Проверено в Chromium и WebKit: 54 сочетания режима (браузер / эмуляция standalone / эмуляция iOS standalone), ширины 320 / 390 / 430 px и safe area 0 / 21 / 34 px. Подтверждены области нажатия не меньше 44 px, отступ для последнего элемента страницы, открытие меню и возврат к браузерным размерам при смене режима. Оставшийся зазор до индикатора Home нужно подтвердить на настоящем iPhone после выкладки.
