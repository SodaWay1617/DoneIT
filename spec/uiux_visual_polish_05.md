# UI/UX 05: визуальный контракт дневного экрана

Дата: 25 октября 2026. Область: только визуальное оформление работающей страницы дня.

## Границы

Не менять Java, JavaScript приложения, маршруты, запросы, сортировку, отбор задач, расчёт времени, права или схему БД. Изменения DOM допустимы только для представления существующих полей. Поведение экранов 01–04 сохраняется.

Референс: [DoneIt: задачи дня на десктопе и мобильном](<Интерфейс DoneIt_ задачи дня на десктопе и мобильном.png>).

## Геометрия

| Элемент | Правило |
|---|---|
| Боковая навигация | Существующие 240 px; без переделки |
| От меню до рабочего поля | 24 px; без центрирования контейнера 1180 px |
| Между списком и правой колонкой | 20 px |
| Правая колонка | 280 px при существующем breakpoint 1200 px |
| Основной список | Оставшаяся ширина, minmax(0, 1fr) |
| Телефон | 8 px по сторонам, без горизонтальной прокрутки |
| Обычная строка ПК | 72 px, рост только при переносе реального содержимого |
| Строка телефона | Базовый минимум 84 px, без обрезки длинных названий |
| Кнопки выполнения/меню | Прежние 44 × 44 px |
| Контейнеры | Не более 8 px скругления; строки — 6 px |
| Правая колонка | Один инструментальный блок с общей поверхностью; без карточек внутри карточек |

Разделители между каждой парой задач убраны. Наведение и фокус выделяют конкретную строку. Просрочка сохраняет мягкий фон и узкий боковой акцент без смещения текста.

## Состояния

- «Хочу»: без пунктирного контура всей строки, с локализованной подписью.
- «Можно»: полная непрозрачность текста и элементов управления, с подписью категории, не имитирующей disabled.
- На телефоне подпись категории находится рядом со временем, чтобы не создавать лишнюю строку метаданных.
- Приоритеты сохраняют текст и собственные спокойные цвета. Название задачи остаётся главным.
- Настоящие disabled/busy состояния кнопок не меняются.
- Русский и английский используют существующий перевод категории; новых строк или значений модели нет.

## Визуальный контроль

Использован одинаковый демонстрационный набор из десяти задач, близкий к референсу по названиям, проектам, оценкам и времени. Сортировка остаётся реальной, поэтому порядок не подгоняется под картинку.

Измерения Chromium на одинаковых данных:

| Метрика | До | После |
|---|---|---|
| Зазор слева при 1920 px | 250 px | 24 px |
| Обычная строка ПК | 72–74 px | 72 px |
| Строка при ширине телефона 390 px | 89–91 px | около 86 px |
| Шрифт метаданных | 11 px | 12 px |
| Прозрачность необязательной задачи | 0.72 | 1 |
| Контур «Хочу» | dashed | solid, прозрачный |
| Ширина правого инструмента | 260 px | 280 px |

Снимки до и после и референс собраны в локальном [отчёте сравнения](../target/visual-comparison.html). Он и изображения лежат в игнорируемом target, не входят в приложение и не поставляются на сервер.

Это не пиксельная копия мокапа: реальные поля, сортировка, размеры касания, мобильная навигация и действия сохранены. Из референса взяты приоритет названия, компактность, спокойные метки и связанное оформление планировочного инструмента.

## Проверка

Полный набор 298 тестов пройден. Вёрстка проверяется отдельно от функциональных тестов:

- Chromium и WebKit: 320, 375, 390, 430, 768, 1024, 1200, 1280, 1440, 1920 CSS px.
- Измеряются зазор от навигации, ширина колонки, высота строк, отсутствие переполнения, opacity и border-style категорий, размеры шрифтов.
- На одинаковых данных сравниваются снимки, а не только успешность HTTP-запросов.
- Дополнительно проверяются длинные слова, названия проектов и теги, фокус клавиатуры, меню регулярки, отмена выполнения и переноса без POST, фильтры и выбор даты.
- Мобильное меню остаётся однострочным из иконок. В эмуляции PWA учитывается safe area 34 px.
- Реальный iPhone Safari/PWA и системная клавиатура остаются открытой проверкой.

На VPS изменения не выкладывались. Пользовательские удаления старых изображений не восстанавливались.
