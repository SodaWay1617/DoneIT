# DoneIt MCP MVP: запуск и использование

MCP находится в том же Spring Boot-приложении. Путь: `/mcp`, транспорт Streamable HTTP, Spring AI 1.1.8 / Java SDK 0.18.3. По умолчанию MCP выключен; остальной DoneIt продолжает работать.

## Актуальный способ: выпуск в настройках по HTTPS

После обновления с миграцией 0032 открыть **Настройки → MCP-токены**
(`/settings/mcp-tokens`). Задать название, срок 1–21 день (по умолчанию 21)
и права: чтение либо чтение и изменение. Нажать «Выпустить MCP-токен»,
скопировать секрет до скрытия/смены вкладки или ухода со страницы.
Повторно получить секрет нельзя; потерянный токен отозвать и выпустить новый.
Секрет не сохраняется в HTML, flash/session, URL или localStorage.
Он доступен в ответе выпуска и буфере обмена пользователя; буфер очищать вручную,
когда секрет больше не нужен. Список содержит только метаданные своих токенов.

В PowerShell установить секрет в переменную без включения его в историю команд:

```powershell
$mcpInput = Read-Host 'Вставьте новый MCP-токен' -AsSecureString
$mcpCredential = [System.Net.NetworkCredential]::new('', $mcpInput)
$env:DONEIT_MCP_TOKEN = $mcpCredential.Password
[Environment]::SetEnvironmentVariable('DONEIT_MCP_TOKEN', $env:DONEIT_MCP_TOKEN, 'User')
Remove-Variable mcpCredential,mcpInput
codex mcp add doneit --url https://done-it-all.ru/mcp --bearer-token-env-var DONEIT_MCP_TOKEN
```

Запустить Codex из этого терминала; VS Code полностью перезапустить для получения
нового окружения. Проверить подключение сначала только на чтение.

Выпуск/отзыв доступны только при HTTPS, действующей браузерной авторизации,
CSRF и включённом `doneit.mcp.enabled`. Нельзя включать доверие к forwarded
headers без закрытия прямого внешнего приложения; см. `https_docker_runbook.md`.
Максимум 32 активных токена на пользователя и 10 выпусков в час; пользовательская
строка блокируется на время проверки лимитов. В БД хранится SHA-256 от
криптографически случайного секрета из 32 байт, права, владелец и срок.
Выпуск/отзыв записываются в mcp_audit без секрета или хеша.

Каждый новый MCP-запрос проверяет БД, поэтому отзыв/истечение срока блокируют
и дальнейшие обращения с уже открытой MCP-сессией. Выполняющийся запрос
не откатывается отзывом; существующий SSE-сокет не является отдельным правом
доступа. Автоматические уведомления MCP выключены. Физически задачи не удаляются.

### Переход с серверного YAML

При первом запуске существующие `doneit.mcp.tokens` переносятся в mcp_tokens
по ID с сохранением владельца, хеша, прав и срока. Отозванные записи не
возрождаются после перезапуска, даже если остались в YAML. Список помечает их
«Перенесён из серверной конфигурации». Импорт требует существующего пользователя.
После проверки UI можно убрать список `tokens` из YAML (либо оставить `tokens: []`);
сохранить enabled, allowed-hosts/origins и прочие настройки транспорта.
Изменение/удаление строки YAML больше не меняет уже импортированный токен:
отзывать его в настройках. Для нового выпуска использовать UI, не повторный
ClientId в YAML. Секретные данные не коммитить.

Серверный YAML теперь нужен только для общих настроек MCP; новые токены
не требуют изменения файлов или перезапуска приложения. Для аварийного
отключения всего MCP установить enabled=false и пересоздать app.
После выпуска собственного нового UI-токена проверить его и отозвать старый
импортированный токен. Не отзывать текущий до сохранения нового секрета.

### Восстановление и откат

Таблица mcp_tokens входит в backup БД. Восстановление старой копии может вернуть
ранее отозванные/действовавшие токены: после восстановления проверить список
и при необходимости отозвать/перевыпустить их. YAML не является источником
истины для уже импортированных токенов. Откат на старый JAR вернёт проверку YAML,
поэтому перед таким откатом убрать из YAML все отозванные записи, иначе старый
код снова разрешит их до истечения срока. UI-токены старый JAR не поддерживает.

Ниже сохранён первоначальный процесс MVP для истории и первоначального bootstrap.
Ограничение 12 часов относится к старому локальному генератору; UI выпускает
токены до 21 дня только через HTTPS.

Проверено 27 октября 2026: полный набор из 317 тестов проходит, включая настоящий HTTP MCP-клиент, CRUD, изоляцию пользователей, read-only, дедупликацию и конкурентные изменения. JAR собран без Docker-сборки. Генератор ключей и Compose override проверены. На VPS пока не развёрнуто.

## Временный прямой HTTP

По поручению пользователя MVP работает напрямую по HTTP, без SSH. HTTPS будет настроен отдельно. В этом временном режиме токен и данные не шифруются в сети. Каждый токен имеет обязательный срок действия; генератор выдаёт его максимум на 12 часов.

Отдельный домен, нейросеть на сервере, дополнительный контейнер или отдельная БД для MCP не нужны. Пользователь токена должен уже существовать в DoneIt.

## Выдача токена на ноутбуке

Из корня репозитория в PowerShell:

```powershell
./scripts/new-mcp-token.ps1 -Username YOUR_DONEIT_LOGIN -ClientId laptop-01 -Hours 12 -Hosts 'VPS_IP' -AllowWrite
```

Заменить `VPS_IP` на реальный IP или hostname, без `http://`, порта и пути. Для локального запуска оставить стандартные Hosts или передать `localhost,127.0.0.1`. При необходимости несколько адресов можно передать массивом.

Генератор сохраняет в игнорируемой `.mcp-local/` два файла:

- `laptop-01.token` — исходный секрет, остаётся на ноутбуке и используется только клиентом;
- `laptop-01.yml` — серверная конфигурация: username, tokenId, SHA-256 хеш, разрешение записи и срок действия. Только этот YAML переносится на сервер.

Секрет не печатается в консоль. На Windows каталог получает доступ только текущего пользователя. Существующие файлы генератор не перезаписывает: для нового ключа выбрать новый ClientId. Без `-AllowWrite` токен только читает задачи. На сервере защитить YAML правами владельца процесса, не размещать в публичной директории и не коммитить.

Пример структуры серверной конфигурации (значения ниже — placeholders, их нельзя использовать как рабочий ключ):

```yaml
doneit:
  mcp:
    enabled: true
    allowed-hosts:
      - VPS_IP
    tokens:
      - id: laptop-01
        username: YOUR_DONEIT_LOGIN
        sha256: REPLACE_WITH_64_HEX_CHARACTERS
        write: true
        expires-at: 'REPLACE_WITH_UTC_EXPIRY'
```

Несколько токенов задаются несколькими элементами `tokens`. ID и хеши должны быть уникальны. Отдельный токен на каждого пользователя/клиента. Браузерная cookie и переданный в инструмент userId не заменяют Bearer-авторизацию.

## Запуск JAR

База и обычная конфигурация приложения остаются прежними. Добавить внешний YAML к существующей команде запуска:

```text
java -jar target/doneit-0.0.1-SNAPSHOT.jar --spring.config.additional-location=file:/ABSOLUTE_PATH/laptop-01.yml
```

Используется существующий порт приложения, например `http://VPS_IP:8080/mcp`. Не нужно менять bind address/порт всего DoneIt ради MCP. После изменения конфигурации токенов нужен перезапуск. Не передавать сам Bearer-токен в аргументах Java, URL или серверном YAML.

При запуске применяется Liquibase 0031: добавляется ревизия обычных задач, журнал MCP и дедупликация создания. Перед production-миграцией нужна резервная копия. До отдельного поручения deploy не выполняется.

## Вариант с уже используемым Docker Compose

Дополнительный файл `docker-compose.mcp.yml` только монтирует YAML и ограничивает файловые Docker-логи. Он не добавляет контейнеров или БД.

1. Скопировать серверный YAML на VPS в защищённый каталог.
2. Установить `DONEIT_MCP_CONFIG_FILE` в абсолютный путь этого файла.
3. Один раз собрать релиз приложения после проверок, если текущий образ ещё не содержит MCP. Не делать сборку для настройки ключа.
4. Запустить существующий сервис с override:

```text
docker compose -f docker-compose.yml -f docker-compose.mcp.yml up -d --no-build --no-deps app
```

`--no-build` требует уже собранный образ приложения. PostgreSQL этот запуск не пересоздаёт. При смене/отзыве ключа достаточно обновить файл и перезапустить сервис, без пересборки образа.

## Настройка MCP-клиента

Нужен клиент с поддержкой Streamable HTTP и пользовательского заголовка Authorization. Параметры подключения:

```text
URL: http://VPS_IP:8080/mcp
Authorization: Bearer <содержимое laptop-01.token без завершающего перевода строки>
```

Конкретный формат файла настроек зависит от клиента. Для первого соединения проверить `initialize` и `tools/list`: должны быть ровно шесть инструментов. Затем `list_projects` сообщает текущую дату и timezone приложения. Проверять запись сначала на отдельной тестовой задаче.

Подтверждение записи обеспечивает MCP-клиент. Включить запрос разрешения для `create_task`, `update_task`, `close_task`; прочитать список изменений перед согласием. `destructiveHint` — подсказка, а не серверное подтверждение человека. Если клиент не умеет согласовывать запись, использовать read-only токен.

## Контракт инструментов

| Инструмент | Параметры |
|---|---|
| `list_projects` | `{}` |
| `list_tasks` | query, projectId, statuses, plannedFrom, plannedTo, cursor, limit (по умолчанию 20, максимум 100) |
| `get_task` | taskId |
| `create_task` | requestId, task |
| `update_task` | taskId, expectedRevision, changes |
| `close_task` | taskId, expectedRevision |

Все ID относятся к обычным задачам; инструменты не работают с регулярками. `code` — отображаемый код задачи, ID — ключ для следующих вызовов. Пагинация идёт по ID по убыванию: `nextCursor` следующего ответа передаётся как `cursor`. Без statuses не показываются DONE/CLOSED. Поиск query — буквальное вхождение в название/описание без SQL wildcard-семантики.

Создание во входящих:

```json
{"requestId":"tickets-2026-10-27-01","task":{"title":"Купить билеты"}}
```

По умолчанию NEW в личном MAIN, REQUIRED, NONE, без времени и оценки. Для работы на дату явно задать TODO:

```json
{"requestId":"tickets-2026-10-27-02","task":{"title":"Купить билеты","status":"TODO","plannedDate":"2026-10-31"}}
```

PATCH с ревизией, полученной последним `get_task`:

```json
{"taskId":42,"expectedRevision":3,"changes":{"title":"Купить билеты на поезд"}}
```

Остальные поля сохраняются. `null` очищает nullable-поле; он не очищает обязательные title/projectId/status/priority/planningType. Теги, исполнители, parent/subtask-связи и фактическое время через MCP не редактируются. Перенос между проектами с несовместимыми исполнителями или задачами в иерархии отклоняется.

Разрешённые поля task/changes: title (до 255 символов), description (до 20000), projectId, status, priority, planningType, plannedDate, plannedForAt, deadlineAt, estimateMinutes, endTime. Статусы/приоритеты/тип планирования — существующие значения enum DoneIt. Создать сразу DONE/CLOSED нельзя.

Даты — ISO и локальное время приложения. Планирование без времени: `plannedDate=YYYY-MM-DD`; со временем: `plannedForAt=YYYY-MM-DDTHH:mm`. Для смены представления очистить прежнее поле. plannedForAt и endTime имеют точность до минуты. При заданном конце интервала оценка вычисляется по существующим правилам; явно переданная противоречащая оценка отклоняется. Перевод в BACKLOG очищает планирование/конец интервала, сохраняя остальные поля.

Закрытие:

```json
{"taskId":42,"expectedRevision":4}
```

`close_task` переводит в CLOSED, не удаляет строку и не означает успешное выполнение. Уже выполненную DONE-задачу этим инструментом отклонить нельзя.

## Повтор, конфликты, ошибки

- При потере ответа создания повторить **тот же** requestId и поля. В одной транзакции сохраняются задача и результат; параллельные повторы не создают дубликат.
- Тот же requestId с другими полями даёт CONFLICT. Ключ ограничен пользователем и tokenId. Не менять tokenId посреди повтора потерянного создания; при ротации сначала найти исходную задачу.
- UPDATE/CLOSE требует expectedRevision. Ревизия растёт при любом UPDATE tasks, в том числе из веб-интерфейса и при неизменных часах. Проверка и запись выполняются под блокировкой строки. После CONFLICT сначала перечитать задачу и согласовать изменения, не подставлять свежую ревизию автоматически.
- HTTP: 401 — токен отсутствует, неверен, истёк или пользователь отсутствует; 403 — недопустимый Host/Origin; 404 — MCP выключен либо чужая/истёкшая MCP-сессия; 413 — тело больше лимита; 429 — лимит частоты.
- Бизнес-ошибки возвращаются в MCP CallToolResult с `isError=true`: VALIDATION_ERROR, NOT_FOUND, FORBIDDEN, CONFLICT, INTERNAL_ERROR. Авторизационные ошибки не перенаправляют на login.
- Если ошибка транспорта не позволяет узнать результат, не предполагать успех или откат: перечитать задачу, а для создания повторить исходный requestId.
- После перезапуска сервера MCP-клиент должен инициализировать новую сессию. Session ID привязан к tokenId/пользователю и не заменяет токен.

## Аудит, отзыв и отключение

`mcp_audit` хранит операции, actor/client, результат и изменения. Успешная запись аудируется в той же транзакции; отказ — после отката. Чтение журналируется метаданными, без копирования всей выдачи. Прежние триггеры истории задач сохранены. Аудит и дедупликация автоматически не очищаются.

Отозвать ключ: удалить его из внешнего YAML и перезапустить приложение. Ротация: выпустить новый ClientId, заменить список ключей на сервере, перезапустить, обновить клиент. Отключить MCP: убрать внешний YAML или установить `doneit.mcp.enabled=false` и перезапустить. Веб-вход, cookie и CSRF при этом остаются прежними.

Лимиты по умолчанию: 64 KiB на тело POST, 120 HTTP-запросов в минуту на tokenId и 600 на весь MCP endpoint, максимум 256 сессий в памяти. Лимиты токена настраиваются через `doneit.mcp.max-request-bytes` и `doneit.mcp.requests-per-minute`. Origin не нужен небраузерному клиенту; браузерный origin должен явно входить в `doneit.mcp.allowed-origins`. Никогда не публиковать токен в URL. Docker override ограничивает stdout-логи приложения до трёх файлов по 10 MiB; Spring rolling policy применяется только при включённом файловом логировании.

## Тесты с экономией Docker

Unit-тесты MCP выполняются без контейнеров. Интеграционные тесты по умолчанию сохраняют Testcontainers. Для уже подготовленного выделенного PostgreSQL можно задать:

```powershell
$env:DONEIT_TEST_JDBC_URL='jdbc:postgresql://127.0.0.1:PORT/doneit_mcp_test'
$env:DONEIT_TEST_DB_USER='doneit'
$env:DONEIT_TEST_DB_PASSWORD='LOCAL_TEST_PASSWORD'
mvn "-Dmaven.repo.local=$PWD/.m2/repository" test
```

Это **только отдельная тестовая БД**: тесты очищают её таблицы. Адаптер не принимает произвольные URL: только loopback-хост, имя с окончанием `_test`, без query options и userinfo. Рабочую doneit или production не использовать. Новые контейнеры и образы при таком прогоне не создаются.
